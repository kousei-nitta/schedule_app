# 要求定義

## プロジェクト概要
大学生（千葉工業大学）向けの、授業・課題・アルバイト・その他の予定を一元管理するスケジュール帳Webアプリ。
開発者本人をペルソナとした個人利用が前提（ログインなし・単一ユーザー・ローカル動作）。
大学の授業の一環としてPDCAサイクルを回しながら開発する。

## 目的
授業・課題・アルバイト・その他の予定を一つのアプリに集約し、必要な情報を適切な形式で登録・確認できる
スケジュール帳を実現する。将来的には確認漏れ・予定の重複・課題忘れ・入力負担の削減を評価する。

## MVPの範囲

### 含む
- 予定の登録・確認・編集・削除（授業・課題・アルバイト・その他）
- 授業の学期一括登録（繰り返し予定の自動生成）
- 学期ごとの休講日の登録（授業の予定の自動生成に反映する）
- 課題の完了管理

### 含まない（将来のPDCAで検討）
- ログイン・認証
- メール／ブラウザ通知
- 大学の出席システムとの連携
- 予定の重複検知
- クラウド化・スマートフォン対応
- 国の祝日・大学の学年暦の自動取り込み（休講日は手動で登録する）

## カテゴリ
- **授業**（時間型）
- **課題**（期限型）
- **アルバイト**（時間型）
- **その他**（時間型／期限型の両方があり得る。登録時にどちらか選択）

「時間型」＝開始・終了時刻が重要。「期限型」＝締切日時と完了状態が重要。

## 機能要件

### カレンダー表示
- 表示単位は「週・月・一覧」の3つ（日・年は作らない）
- 週表示は日曜始まり。今日を含む週が初期表示、前後の週に移動でき、「今日」ボタンで戻れる
- 月表示は俯瞰用。1日3件までタイトル表示、4件目以降は「＋N件」にまとめ、クリックでその日の週表示へ
- 一覧表示は時間型の予定（授業・アルバイト・その他の時間指定あり）を今日以降、日付順に表示。期限型は含まない
- カテゴリによる絞り込みができる（初期状態は全カテゴリ表示）
- 画面の一角に「直近の締切」欄を常に表示する（今日から1週間以内の未完了と期限切れを締切順に表示。範囲・件数は調整可能。カテゴリ絞り込みの影響を受けない）

### 学期
- 学期は、名前・開始日・終了日で登録する。授業は必ず1つの学期に所属する
- 学期名は、年度と「前期」「後期」のどちらかを選んで決め、「2026年度 前期」の形にする。前期・後期以外の学期は、現時点では扱わない
- 年度は4月始まりとする（1〜3月は、前年度に属する）
- 開始日と終了日は、どちらも必須。終了日は、開始日より後でなければならない
- 同じ名前の学期は、重複して登録できない。期間が重なる学期は、登録できる
- 学期の変更・削除の扱いは、現時点では未決定
- 学期ごとに、授業が行われない日（休講日）を、日付で登録できる。大学の学年暦などで確認した日を、手動で登録する（大学独自の休みの日や、授業が行われない祝日など。各学期で数日程度を想定）
- 登録した休講日には、その学期に所属するすべての授業の予定を作らない
- 授業を登録したあとに休講日を追加・削除した場合も、すでに作られた授業の予定に反映する
- 国の祝日を一律に休講日とする処理と、大学の学年暦の自動取り込みは、現時点では行わない（授業が行われない祝日は、休講日として登録する）
- 授業は基本的に1学期13回だが、13回を予定の自動生成の件数の上限にはしない（授業の予定は、学期の期間・曜日・休講日で決める）
- 別の曜日の時間割で授業を行う日（曜日の読み替え）の扱いは、大学の学年暦を確認するまで未決定

### 予定の登録
- カレンダーの空き枠を1クリックすると、日時入力済みの追加フォームがその場で開く（アルバイト・その他・単発の授業用）
- 必須項目は「カテゴリ・日付・開始/終了時刻・タイトル」（時間型）、詳細・メモは任意
- **授業モード**：科目名・教室（任意）・曜日・開始/終了時刻（9〜19時のプルダウン、1時間刻み）・詳細/メモ（任意）を入力。
  学期は授業ごとではなく学期につき一度だけ登録し（「学期」の項を参照）、授業は1つの学期に所属する。授業を登録すると、その学期の期間内の該当曜日へ毎週分の予定が自動生成される（学期に登録した休講日を除く）
  （1科目週1回が基本。週2回ある場合は同じ科目名で2回登録）
- **課題・タスクモード**：課題名・対象授業（授業一覧から選択、必須）・締切日時を必須、詳細・メモは任意
- **その他**：登録フォーム内で「時間指定あり（初期値）／締切のみ」を切り替える。時間指定ありは授業に紐づかない時間型の予定、
  締切のみは授業に紐づかない期限型のタスク（課題・タスクモードの一覧に一緒に載る。対象授業欄は空）
- **アルバイト**：タイトル（仕事内容）・派遣会社（任意の専用項目。自由入力＋過去の入力候補）・開始/終了時刻（自由入力。
  9〜19時のプルダウンには縛らない）
- 複数日程のアルバイトは1日ずつ登録する（一括生成オプションは作らない）
- カレンダーから単発の授業（補講など）を追加する際は、タイトルを自由入力にせず授業一覧から選択する

### 予定の確認
- 予定をクリックすると詳細パネルが開き、教室・派遣会社・メモなどを確認できる
- 課題・タスクモードで未完了・完了の課題を確認できる

### 予定の編集・削除
- 単発の予定・課題は詳細パネルから編集・削除する
- 授業の編集・削除は、次の3つを区別する
  - **授業全体の編集**：授業モードから行う。今日以降の、自動生成された予定に反映される（下の作り直し）
  - **授業全体の削除**：授業モードから行う。過去分を含む、その授業の予定（自動生成・単発とも）と、紐づく課題がまとめて削除される（確認ダイアログに件数を表示）
  - **カレンダーからの授業の予定の編集・削除**：その日の予定だけに反映される（授業全体の設定は変わらない）
- 授業全体の編集では、自動生成された今日以降の予定が、個別に変更・削除した日も含めて設定どおりに作り直される（保存前に確認メッセージ）。学期の休講日には、作り直しでも予定を作らない。カレンダーから追加した単発の授業（補講など）は作り直しの対象にならず、そのまま残る（休講日の追加・削除でも変わらない。同じ日に、自動生成された授業の予定と並ぶことがある）
- カテゴリは編集で変更できない（間違えたら削除して登録し直す）

### 課題の完了管理
- 課題・タスクモードの一覧・「直近の締切」欄・詳細パネルのどこからでも1クリックで完了・未完了を切り替えられる
- 完了の取り消しは可能。削除とは異なり確認ダイアログは出さない
- 完了にした課題はカレンダー（週・月表示）から消え、課題・タスクモードの完了一覧でのみ確認できる
- 「完了も表示」の切り替えはMVPでは作らない

## 非機能要件
- **動作環境**：MacBookのローカル環境、Chrome
- **性能**：個人利用の規模のため、特別な要件は設けない。扱う予定の件数は、授業の予定の自動生成により、1学期あたり数百件程度になる（学期を重ねると、その分増える）
- **セキュリティ**：ログインなし・自分専用のローカル動作のため最小限。manaba等の外部サービス認証情報は扱わない
- **保守性**：開発者自身が読んで理解・修正できるコードであること（PDCAの評価対象でもある）
- **データ**：SQLiteのローカルファイル1つで完結。初期段階ではバックアップの仕組みは作らない
