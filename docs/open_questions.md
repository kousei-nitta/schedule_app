# 未決定事項と将来の検討事項

## 未決定事項
現時点で決まっていない事項の一覧。**実装側（Copilot）は、これらを自分の判断で決めない。** 該当する実装に入る前に、開発者（Koma）が決定し、このファイルを更新する。決めるタイミングは、各項目に書いたとおり。

| 項目 | 内容 | 決めるタイミング |
|---|---|---|
| 曜日の読み替え（振替授業日） | 大学が、ある日に別の曜日の時間割で授業を行う日（例：ある木曜日に、水曜日の授業を行う）を、アプリで扱うか。扱う場合は、休講日と同じく学期ごとに登録し、その日の本来の曜日の授業の予定を作らず、指定した曜日の授業の予定を作る方式が考えられる（休講日のテーブルに「その日に行う曜日」の項目を足す方法と、別のテーブルにする方法がある）。判断の材料：①大学の学年暦（過去2〜3学期分）に、このような日があるか、学期ごとに何日あるか ②休講日だけを登録したときに、曜日ごとの授業日数が基本の13回からずれる曜日があるか ③祝日に授業を行う日があるか（ある場合は、その日を休講日として登録しないだけで済む）。年に0〜1日程度なら、カレンダーから単発の授業として追加する運用でも足りる（ただし、単発の授業は、授業全体の編集による作り直しの対象にならず、教室・時刻を変えても、その日の予定は変わらない）。それまでは扱わない（読み替えた曜日の授業の予定を作らない） | 大学の学年暦を確認したあと |

- 「学期の変更・削除時の扱い」は、2026-10-20に決めた（期間の変更は、変わった部分だけを予定と休講日に反映する。授業がある学期は削除できない。「学期の期間の変更と予定の同期」と「学期API」）。授業の所属学期の付け替えは、2026-10-13に決めた（付け替えない。「授業API」）
