# UI/UX

> このファイルは設計上の正本です。変更が必要な場合は `.github/copilot-instructions.md` の変更手順に従い、開発者（Koma）の承認を得てから更新します。

## 画面構成
アプリ下部の切り替えボタン群で、次の3モードを切り替える。

| モード | 役割 |
|---|---|
| カレンダー | 時間型の予定の登録・確認・編集・削除、期限型の締切の俯瞰（その他（締切のみ）の登録と、締切の編集・削除を含む） |
| 授業 | 授業（科目）の学期一括登録・一覧・編集・削除。学期の休講日の登録 |
| 課題・タスク | 課題と期限型のその他の一覧・登録・完了管理 |

## カレンダーモード

### 表示単位
週（初期表示）・月・一覧の3つ。切り替えても、見ている日付は保つ。

- 画面の上部に、カテゴリの絞り込み（「共通」）を置き、その下に、前へ・次へ・「今日」のボタン、表示中の期間、表示の切り替えのボタン（週・月・一覧）を並べる
- 「今日」は、ブラウザの日付（学期の初期選択と同じ）

### 週表示
- 日曜始まり（日曜〜土曜）。今日を含む週が初期表示。前後の週へ移動でき、「今日」ボタンで元の週に戻れる
- 時間軸のブロックで時間型の予定を表示する。ブロックには **タイトル＋時間のみ** を表示し、教室・メモなどの詳細は隠す
- 時間軸は0〜24時の全体。最初は、8時が上端になるように表示する（時間軸の範囲を狭めると、範囲の外の予定（深夜のアルバイトなど）が表示されなくなるため）
- 時間軸の上に「締切」の行（行の見出しは「締切」）を設け、未完了の期限型（課題・その他（締切のみ））を、締切日の列に、●の印（カテゴリの色）とタイトルで並べる（時刻は出さない）。時間軸は占有しない（2026-10-18に決定）
  - 同じ日の締切は、締切日時の早い順に並べる
  - 締切がない週も、行を出す。締切が多い日は、行が高くなる（件数の上限は設けない）
  - タイトルが長いときは、枠の中で切れる（全体は、詳細パネルで確認する）

### 月表示
- 俯瞰用。各日にはタイトルだけの短い表示を並べる。時間型の予定は、時刻を出さず、カテゴリの色のブロックに、タイトルを表示する
- 期限型（未完了の締切）は、締切日に、●の印（カテゴリの色）とタイトルで表示し、時間型の色のブロックと見分けられるようにする。その日の時間型の予定より上に、締切日時の早い順に並べる（2026-10-18に決定）
- 1日3件までタイトルを表示し（締切を含む）、4件目以降は「＋N件」にまとめる
- 日付または「＋N件」のクリックは、どちらもその日を含む週の週表示へ移る

### 一覧表示
- 時間型の予定（授業・アルバイト・その他の時間指定あり）のみを、今日以降を初期表示として日付順に縦に並べる。期限型は載せない（週・月の表示から一覧表示に切り替えるときも、締切を一瞬も出さない）
- 表示する期間は、28日間（4週間）。初めて開いたときと、「今日」ボタンを押したときは、今日からの28日間。前後への移動は、28日ずつ。週・月の表示から切り替えたときは、見ていた日付からの28日間（週・月の表示で、前後への移動や、日付・「＋N件」のクリックで表示を変えたあとは、その週・月の最初の日から）
- 日付ごとに見出し（曜日つき）を置き、その下に、その日の予定の行を並べる。予定のない日は、出さない。期間に予定が1件もなければ、「表示する予定はありません」
- 行には日付・時間・タイトルに加え、カテゴリごとの主要項目を表示する（アルバイト＝派遣会社、授業＝教室。値がなければ出さない）。タイトルの前に、カテゴリのアイコンを付ける

### 共通
- カテゴリによる絞り込みができる（初期状態は全カテゴリ表示）
  - 画面の上部に、カテゴリごとのチェックボックス（色の見本つき）を並べる。外したカテゴリの予定は、週・月・一覧のどの表示にも出さない。ページを再読み込みすると、初期状態に戻る
  - 選択肢の並びは、授業・課題・アルバイト・その他（2026-10-18に決定）。外したカテゴリの締切も、週・月の表示に出さない
  - その他の選択肢は、時間指定ありの予定と、締切のみの課題・タスクの両方を切り替える（どちらも同じ「その他」で、色・アイコンも同じため、1つの選択肢にする）
- 「直近の締切」欄を、カレンダーの右の列に常に表示する（画面の幅が992px未満のときは、カレンダーの下。2026-10-18に決定）。カテゴリの絞り込みの影響を受けない
  - 載せる範囲：未完了の課題・タスクのうち、期限切れのもの（すべて）と、締切日が今日から7日後までのもの（今日を含めて8日間。来週の同じ曜日の締切まで入る）。件数の上限は設けない。並びは、締切日時の早い順（期限切れが上に来る）
  - 見出しは「直近の締切」。その下に、小さく「期限切れと、今日から7日後までの、未完了の課題・タスク」
  - 各行には、上から、締切（「2026年10月20日（火） 23:59」の形。期限切れは、赤い「期限切れ」の印）、カテゴリのアイコンとタイトル、対象授業（その他（締切のみ）は出さない）を表示し、左に完了のチェックボックスを置く。アイコンとチェックボックスの名前（`aria-label`）は、課題・タスクモードの一覧と同じ形（アイコンは読み上げず、カテゴリの表示名を見えない文字で添える。名前は「「レポート第1回」（締切 2026年10月20日（火） 23:59）の完了」）。区切れる場所のない長い文字列も、欄の中で折り返す
  - 0件のときは、「直近の締切はありません」
  - 「今日」と、期限切れかどうかは、ブラウザの日付・時刻で決める（課題・タスクのAPIは「今日」を使わず、未完了の課題・タスクをまとめて返す。`architecture.md` の「課題・タスクAPI」）。判定は、欄を作り直すときに行う（表示したまま時間が過ぎても、作り直すまで変わらない）
  - 取得中は「読み込み中…」、取得に失敗したときは、欄の中に、エラーメッセージと「再読み込み」ボタンを表示する（カレンダーの締切は、それまでに表示していたものが残る）
  - 完了の切り替え：チェックボックスを押すと、すぐに保存する（確認のダイアログは出さない）。保存中は、そのチェックボックスを押せない。保存できたら、取得し直す（完了にしたものは、欄と、カレンダーの締切から消える）。失敗したら、チェックを元に戻し、エラーメッセージを欄の上部に表示する（次の切り替えを始めるときと、カレンダーのモードを開き直したときに消す）
  - 欄の行を押しても、詳細パネルは開かない（詳細は、カレンダーの締切から開く）
- 期限を過ぎて未完了の課題は消さずに残す（完了にすれば期限切れの表示から外れる）
- カレンダーのモードを開くたびに、予定と、未完了の課題・タスクを取得し直す（授業モードで登録した授業や、休講日の追加・削除、課題・タスクモードでの課題の追加・編集・削除・完了の切り替えを、カレンダーと「直近の締切」欄に反映するため）
- 予定の取得中は、「読み込み中…」を表示する。取得に失敗したときは、カレンダーの上に、エラーメッセージと「再読み込み」ボタンを表示する（それまでに表示していた予定は、残ることがある）。カレンダーの部品（FullCalendar）を読み込めなかったときは、カレンダーの代わりに、ページの再読み込みを促すメッセージを表示する（「直近の締切」欄も出さない。ほかのモードは使える）
- ボタンなどの文言は、日本語にする（今日・週・月・一覧、「＋N件」、「表示する予定はありません」。ボタンにマウスを重ねたときに出る説明も、日本語）

### 予定の追加（2026-10-19に詳細を決定）
- 空き枠を1クリックすると、クリックした日時が入った状態で追加フォーム（モーダル）がその場で開く。入る値は、クリックした場所で決まる
  - 週表示の時間軸：クリックした日と、30分の枠の始まりの時刻（開始時刻）。終了時刻は、開始時刻の1時間後（23時台の枠は 23:59。日付をまたぐ予定は、1件では登録できないため）
  - 週表示の「締切」の行：その日。カテゴリは「その他」の「締切のみ」を選んだ状態で開く（締切時刻は 23:59）
  - 月表示の日付の枠：その日。時刻は 09:00〜10:00（「締切のみ」に切り替えたときの締切時刻は 23:59）
  - 一覧表示：開かない（空き枠がないため）
  - 予定・締切のクリックは、詳細パネルを開く。月表示の日付の数字と「＋N件」のクリックは、週表示へ移る（どちらも、追加フォームは開かない）
  - キーボードや一覧表示から追加するための入口（「予定を追加」のボタンなど）は、作らない（要求定義どおり、空き枠のクリックだけ。必要になったら足す）
- 見出しは「予定を追加」。上部に、カテゴリの選択（ボタンの形の3つの選択肢。並びは、授業（補講など）・アルバイト・その他）を置く。初期値は「アルバイト」（カレンダーから追加する予定で、最も多いと考えられるため。授業の予定は、授業の登録で作られる）。課題は、ここでは追加しない（課題・タスクモードから追加する）
- カテゴリを選ぶと、フォームの項目がそのカテゴリ用に切り替わる。切り替えても、入力した値は残る（タイトル・日付・時刻・詳細／メモなど、共通の欄）

  | カテゴリ | 項目（上から） |
  |---|---|
  | 授業（補講など） | 授業・日付・開始時刻・終了時刻・教室（任意）・詳細／メモ（任意） |
  | アルバイト | 仕事内容・派遣会社（任意）・日付・開始時刻・終了時刻・詳細／メモ（任意） |
  | その他（時間指定あり） | タイトル・日付・開始時刻・終了時刻・詳細／メモ（任意） |
  | その他（締切のみ） | タイトル・締切日・締切時刻・詳細／メモ（任意） |

- 時刻（開始・終了・締切）は、すべて自由入力の時刻の入力欄にする（授業の登録のような、9〜19時のプルダウンにしない。クリックした枠の時刻が、そのまま入るため）。開始時刻を変えて、終了時刻が開始時刻以下になったときは、終了時刻を、開始時刻の1時間後に、自動で合わせる（授業の登録と同じ。23時台は 23:59）
- アルバイト：タイトル（仕事内容）・派遣会社（任意）・開始／終了時刻（自由入力）・詳細／メモ（任意）。派遣会社は自由入力で、過去に入力した派遣会社名を入力候補に出す（候補は、予定APIの派遣会社の候補。新しく使った順。`architecture.md` の「予定API」）。候補は、フォームを開くたびに取得する。取得に失敗しても、何も表示せず、候補なしで入力できる（入力の補助のため）
  - 欄の名前は「仕事内容」だが、APIのエラーメッセージは「タイトル」（例：「タイトルは必須です」）のまま表示する（エラーは、仕事内容の欄の下に出るため。課題名と同じ）
  - 終了時刻は、開始時刻より後にする。日付をまたぐ勤務（例：22:00〜翌2:00）は、日付ごとに2件に分けて登録する（22:00〜23:59 と、翌日の 00:00〜02:00。2026-10-19に決定。`architecture.md` の「データ設計」のEvent）
- その他：カテゴリの選択の下に、「時間指定あり（初期値）／締切のみ」の選択を出す。「締切のみ」に切り替えると、クリックした日時が締切日時の初期値になる。締切のみは、課題・タスクのAPIで、その他（`other`）として登録する（課題・タスクモードの一覧に載る。対象授業はない）
- 授業（補講など単発）：タイトルは自由入力にせず、授業モードの登録済み授業から選ぶ（プルダウン。先頭は「選択してください」。予定のタイトルは、選んだ授業の科目名になる）
  - 選択肢は、今の学期の授業（課題の対象授業と同じ規則。欄の下の表示（「2026年度 後期の授業から選びます」など）も同じ。「課題・タスクモード」の「追加」）。クリックした日を含む学期の授業にはしない（日付を変えるたびに選択肢が変わり、期間が重なる学期の扱いも要るため。2026-10-19に決定）
  - 教室などは登録済みの内容が初期値になる：授業を選ぶと、その授業の教室を、教室の欄に入れる（選び直すたびに入れ直す。教室のない授業は、空にする）。時刻は、クリックした時刻のまま（授業の時刻は入れない。補講は、通常と別の時間に行うことが多く、クリックした枠が、その時間のため）。詳細／メモは、空のまま
  - 授業の一覧は、フォームを開くたびに取得する。取得中は、欄の下に「授業を読み込み中…」。取得に失敗したときは、欄の下に、エラーメッセージを表示する（選択肢は「選択してください」だけになり、授業の予定は登録できない。ほかのカテゴリは登録できる）
  - 同じ授業・同じ日付に予定があっても、知らせない（通常の授業と、別の時間の補講が並ぶのは、正しい状態のため。2026-10-19に決定。`architecture.md` の「カレンダーからの授業の予定の操作」）
- ボタンは「キャンセル」と「登録する」。空の必須項目は、ブラウザ標準の入力チェックで止める。それ以外の入力チェックは、サーバー（API）が行い、結果を、該当する入力欄の下に表示する（締切日時のエラーは、締切日・締切時刻の下に、まとめて表示する）。項目に結びつかないエラーは、フォームの上部に表示する
- 送信中は、「登録する」ボタンを無効にして、「登録中…」と表示する。失敗したら、元に戻す（モーダルは開いたまま）
- 登録できたら、モーダルを閉じ、カレンダーの予定を取得し直す（締切のみは、カレンダーの締切と「直近の締切」欄を取得し直す）。メッセージは出さない（アルバイトは、下の知らせを出す）
- アルバイトを登録できたら、カレンダーの上（絞り込みの下）に、「「仕事内容」（2026年10月24日（土） 17:00 〜 21:00）を登録しました。」と、「同じ内容で別の日も登録」ボタン、閉じるボタン（×）を出す。「同じ内容で別の日も登録」を押すと、アルバイトを選び、日付以外（仕事内容・派遣会社・開始時刻・終了時刻・詳細／メモ）を入れた追加フォームが、もう一度開く（日付は空。最初のフォーカスは、日付の欄）。知らせは、追加フォームを開いたとき（このボタンで開いたときを含む）、カレンダーのモードを開き直したとき、×を押したときに消す（2026-10-19に決定。登録した予定を、カレンダーで確かめてから、次の日を入れられるようにするため）
- 開くたびに、入力値・エラー表示を消し、クリックした日時と初期値を入れる。最初のフォーカスは、授業は授業の欄、アルバイト・その他はタイトル（仕事内容）の欄

### 予定の確認・編集・削除
- 予定（ブロック）をクリックすると詳細パネルが開き、教室・派遣会社・メモなどを確認できる。ここから編集・削除する（締切の●をクリックしたときは、下の「締切の詳細パネル（課題・タスク）」）
- 詳細パネル（モーダル）には、タイトル、カテゴリ（アイコンと表示名）、日付（曜日つき。例：「2026年11月18日（水）」）、時間（「17:00 〜 21:00」）、教室、派遣会社、詳細／メモを表示する。教室・派遣会社・詳細／メモは、値がなければ、その行を出さない。詳細／メモの改行は、そのまま改行して表示する
- 詳細パネルの下に、「削除」（左）、「編集」「閉じる」（右）のボタンを置く（2026-10-19に決定）。「編集」「削除」を押すと、詳細パネルを閉じてから、編集のモーダル・削除の確認のモーダルを開く（2つのモーダルを重ねて開かないため）。編集・削除をキャンセルしても、詳細パネルには戻らない
- 編集フォームは、登録時と同じ項目が入力済みの状態で開く。カテゴリと、授業の予定の授業は、変更できない
- カレンダーから授業の予定を編集・削除すると、その日だけに反映される
- 自動生成された授業の予定は、日付を変えられない（時刻・教室・詳細／メモだけ）。別の日に移すときは、その予定を削除し、移す先の日に単発の授業を追加する。単発の予定（補講・アルバイト・その他）は、日付も変えられる（2026-10-19に決定。`architecture.md` の「カレンダーからの授業の予定の操作」）
- 削除の前には必ず確認ダイアログを出す。削除の取り消し（元に戻す）機能は作らない
- 詳細パネルのタイトル・教室・派遣会社・メモは、区切れる場所のない長い文字列も、折り返して表示する（2026-10-18に決定）

#### 編集（モーダル。2026-10-19に決定）
- 見出しは「予定を編集」。登録とは別のモーダルにする（授業・課題の編集と同じ。追加には、カテゴリの切り替えと、アルバイトの知らせがあり、動きが違うため）
- 上部に、カテゴリ（アイコンと表示名）を表示する（変えられない）

  | 予定 | 項目（上から） |
  |---|---|
  | 授業（自動生成） | 授業（表示だけ）・日付（表示だけ）・開始時刻・終了時刻・教室（任意）・詳細／メモ（任意） |
  | 授業（単発） | 授業（表示だけ）・日付・開始時刻・終了時刻・教室（任意）・詳細／メモ（任意） |
  | アルバイト | 仕事内容・派遣会社（任意）・日付・開始時刻・終了時刻・詳細／メモ（任意） |
  | その他（時間指定あり） | タイトル・日付・開始時刻・終了時刻・詳細／メモ（任意） |

  - 授業の「授業」には、予定のタイトル（追加・作成したときの授業の科目名の控え）を表示する
  - 自動生成の授業の予定は、日付の下に、小さく「授業の登録で作られた予定のため、日付は変えられません。別の日に移すときは、この予定を削除して、移す先の日に、単発の授業（補講など）を追加してください。授業全体を編集すると、今日以降のこの授業の予定は、授業の設定どおりに作り直されます（ここで変えた内容も、元に戻ります）。」を表示する
- 時刻の入力と、開始時刻を変えたときの終了時刻の合わせ方、派遣会社の入力候補（開くたびに取得）は、追加と同じ
- 開くたびに、その予定の今の値（詳細パネルに表示していた値）を入力欄に入れ、エラー表示を消す。最初のフォーカスは、授業は開始時刻の欄、アルバイト・その他はタイトル（仕事内容）の欄
- 保存では、変えられる項目を、すべて送る（変えていない項目も、今の値のまま送る）。変えられない項目（カテゴリ・授業・授業の予定のタイトル・自動生成の予定の日付）は送らない
- ボタンは「キャンセル」と「保存する」。入力チェックとエラーの表示は、追加と同じ。送信中は、「保存する」ボタンを無効にして、「保存中…」と表示する。失敗したら、元に戻す（モーダルは開いたまま。ほかの場所で削除された予定は、フォームの上部に「予定が見つかりません」）
- 保存できたら、モーダルを閉じ、カレンダーの予定を取得し直す（メッセージは出さない）

#### 削除（確認のモーダル。2026-10-19に決定）
- 見出しは「予定を削除」。ブラウザ標準の確認ダイアログ（`confirm`）は使わない（授業・課題の削除と同じ）
- 上から、「「タイトル」（2026年11月18日（水） 17:00 〜 21:00）を削除します。」、自動生成の授業の予定だけ「授業の登録で作られた予定です。授業全体を編集すると、今日以降の分は、作り直されます。」、「削除は取り消せません。」を表示する（予定は、一緒に削除されるデータを持たないため、件数は出さない）
- モーダルと「削除する」ボタンには、読み上げで、削除の対象・注意・「削除は取り消せません。」が伝わるように、説明（`aria-describedby`）を付ける（自動生成でない予定では、注意の文字を空にする）
- ボタンは「キャンセル」と「削除する」。最初のフォーカスは「キャンセル」（取り消せない操作のため）
- 削除中は、「削除する」ボタンを無効にして、「削除中…」と表示する。失敗したら、元に戻し、エラーメッセージをモーダルの中に表示する（モーダルは開いたまま）
- 削除できたら、モーダルを閉じ、カレンダーの予定を取得し直す（メッセージは出さない）

#### 追加・編集・削除の共通
- モーダルを閉じて、開き直したあとに、前に開いたときの操作の結果（成功・失敗、授業の一覧）が届いても、開き直したモーダルの表示は変えず、閉じない。カレンダーは取得し直す（`architecture.md` の「JavaScriptの構成」の、モーダルの中で始める要求の規則）

### 締切の詳細パネル（課題・タスク）（2026-10-18に決定）
- 週・月の表示の締切（●とタイトル）をクリックすると、課題・タスクの詳細パネル（モーダル）が開く。予定の詳細パネルとは別のモーダルにする（項目と、使うAPIが違うため）
- 見出しは、タイトル。その下に、カテゴリ（アイコンと表示名）、締切（「2026年10月20日（火） 23:59」の形。未完了で期限切れなら、赤い「期限切れ」の印）、対象授業（その他（締切のみ）は、行を出さない）、詳細／メモ（値がなければ、行を出さない。改行は、そのまま改行して表示する）を表示する。期限切れは、パネルを開いたときの、ブラウザの日付・時刻で判定する。区切れる場所のない長い文字列も、折り返して表示する
- その下に、「完了」のチェックボックスを置く。押すと、すぐに保存する（確認のダイアログは出さない）。パネルは開いたまま（チェックを外せば、未完了に戻せる）
  - 保存中は、チェックボックスを押せない
  - 保存できたら、期限切れの印を、完了の状態に合わせる（完了なら出さない）。カレンダーの締切と「直近の締切」欄は、取得し直す（完了にした締切は、カレンダーから消える）
  - 失敗したら、チェックを元に戻し、エラーメッセージを、パネルの中（上部）に表示する。次の切り替えを始めるときと、パネルを開き直したときに消す
  - 保存が終わったら（成功・失敗とも）、チェックボックスにフォーカスを戻す（押せなくしたときに、フォーカスがパネルの外に移り、Escapeキーでパネルを閉じられなくなるため）
- パネルの下に、「削除」（左）、「編集」「閉じる」（右）のボタンを置く（2026-10-19に決定）。「編集」「削除」を押すと、パネルを閉じてから、課題・タスクモードと同じ、編集のモーダル・削除の確認のモーダル（「課題・タスクモード」の「編集」「削除」）を開く（同じ画面を2つ作らないため。`architecture.md` の「モード間の連携」）。キャンセルしても、パネルには戻らない
- 編集・削除できたら、カレンダーの締切と「直近の締切」欄を取得し直す
- パネルを閉じて、別の締切のパネルを開いたあとに、前の保存の結果が届いても、開いているパネルの表示は変えない（カレンダーの締切と「直近の締切」欄は、取得し直す）

## 授業モード

### 学期（タブと登録）

**表示**
- 授業モードの上部に、学期タブと「新しい学期を登録する」ボタンを置く。本文には、選択中の学期の名前と期間を表示する。期間は、「2026年9月21日 〜 2026年12月27日」の形で表示する
- タブは、開始日の新しい順に左から並べる（開始日が同じなら、あとから登録した学期が左）。数が増えたら、横にスクロールできるようにする
- 過去の学期も、通常のタブと同じ見た目で選べる（特別な印は付けない）

**初期選択**（「今日」は、ブラウザの日付）
1. 今日を含む学期。複数あるときは、タブの並びで左にある学期（開始日が新しい学期）
2. なければ、今日より後に始まる学期のうち、最も早く始まるもの
3. なければ、最も最近終わった学期（終了日が最も新しいもの）
4. 学期が1件もなければ、空状態を表示する

- 2.・3. で、同じ開始日（または同じ終了日）の学期が複数あるときも、タブの並びで左にある学期を選ぶ

**読み込み中・取得失敗**
- 学期の一覧を取得している間は、「読み込み中…」を表示する
- 取得に失敗したときは、エラーメッセージと「再読み込み」ボタンを表示する。押すと、取得をやり直す

**空状態（学期が0件）**
- タブは出さず、説明文と「最初の学期を登録する」ボタンだけを表示する（「新しい学期を登録する」ボタンは出さない。ボタンが2つ並ばないようにするため）

**新しい学期の導線**
- 学期が1件以上あり、今日がどの学期にも含まれないときは、バナーを表示する。バナーには、「新しい学期を登録しますか」という文言と、押すと登録フォームを開く「登録する」ボタンを置く
- 学期が0件のときは、バナーを出さない（空状態の表示だけ）
- 「新しい学期を登録する」ボタンは、学期が1件以上あるとき常に表示し、いつでも登録を始められる（0件のときは、空状態の「最初の学期を登録する」ボタンで登録を始める）

**登録フォーム**（モーダル）

| 項目 | 入力 | 必須 | 初期値 |
|---|---|---|---|
| 年度 | 数値 | 必須 | 今日の年度（4〜12月は今年、1〜3月は前年） |
| 種別 | 前期／後期の選択 | 必須 | 今日が4〜8月なら前期、9〜3月なら後期 |
| 開始日 | 日付 | 必須 | 空欄 |
| 終了日 | 日付 | 必須 | 空欄 |

- 学期名は、年度と種別から「2026年度 前期」の形に組み立てる（名前の入力欄は設けない）
- 期間（開始日・終了日）の初期値は設けず、空欄から入力する
- ボタンは「キャンセル」と「登録する」
- 空の項目は、ブラウザ標準の入力チェックで止める。それ以外の入力チェックは、サーバー（API）が行い、結果を「入力エラーの表示」のとおりに表示する
- 送信中は、「登録する」ボタンを無効にして、「登録中…」と表示する。失敗したら、元に戻す
- フォームを開くたびに、入力値を初期値に戻し、エラー表示を消す

**入力エラーの表示**
- エラーのある項目の下に、メッセージを表示する
- 学期名に関するエラー（形式、同じ名前が登録済み）は、年度・種別の入力欄の下に表示する

**登録後**
- モーダルを閉じ、学期の一覧を取得し直して、登録した学期を選択状態にする

**編集・削除**
- 学期の編集・削除の操作は、現時点では用意しない（「学期の変更・削除時の扱い」が決まるまで。`architecture.md` の「未決定事項」を参照）

### 休講日
学期ごとに、授業が行われない日（休講日）を登録する。大学の学年暦などで確認した日を、学期ごとに手動で登録する（各学期で数日程度を想定）。登録した休講日には、その学期のすべての授業の予定が作られない。授業を登録したあとに、休講日を追加・削除しても、授業の予定に反映される。

**表示**
- 選択中の学期の本文（名前・期間）の下、授業の一覧の上に、「休講日」の欄を置く。学期を切り替えると、その学期の休講日に切り替わる。学期が0件のとき（選択中の学期がないとき）は、欄を出さない
- 欄の中は、上から、見出し「休講日」、欄の上部のエラーの表示（追加の、項目に結びつかないエラーと、削除のエラー）、休講日の一覧、追加の入力欄の順に置く
- 一覧は、日付の昇順。各行に、日付（曜日つき。例：「2026年5月15日（金）」）、名前（なければ表示しない）、「削除」ボタンを置く。日付の表示の処理は、学期の期間の表示と共通にする（`architecture.md` の「JavaScriptの構成」の `dates.js`）
- 「削除」ボタンには、読み上げで、どの休講日のボタンかを区別できるように、「2026年5月15日（金）の休講日を削除」の形の名前（`aria-label`）を付ける
- 0件のときは、「休講日は登録されていません」を表示する
- 取得中は「読み込み中…」、取得に失敗したときは、エラーメッセージと「再読み込み」ボタンを表示する（授業の一覧と同じ）
- 学期を切り替えると、追加の入力欄を空に戻し、エラーの表示を消す（ほかの学期への入力や、ほかの学期で出たエラーを残さないため）

**追加**
- 欄の中に、日付（必須）と名前（任意。例：「開学記念日」）の入力欄と、「追加する」ボタンを置く（モーダルにしない。各学期で数日程度のため）
- 空の日付は、ブラウザ標準の入力チェックで止める。それ以外の入力チェック（学期の期間の外、すでに登録した日付、名前の文字数など）は、サーバー（API）が行い、結果を、該当する入力欄の下に表示する。項目に結びつかないエラーは、欄の上部に表示する（授業の登録フォームと同じ）。日付の入力欄には、学期の期間で選べる日を制限する設定（`min`・`max`）を付けない（入力チェックを、ほかのフォームと同じく、APIにそろえるため）
- 追加できたら、一覧に反映し、入力欄を空に戻して、日付の入力欄にフォーカスを移す（続けて追加できるようにするため）。その日の授業の予定（自動生成のもの）は、削除される。単発の予定（補講など）は、削除されない
- 確認のダイアログは出さない（その日の授業の予定をなくすことが、休講日を追加する目的のため。休講日を削除すれば、その日の予定は作り直される。作り直しの規則は、`architecture.md` の「休講日の変更と予定の同期」）。カレンダーで個別に編集した、その日の自動生成の予定も削除されるが、これも確認しない（休講日の追加は、その日に授業がないことの登録で、個別に変えた予定が消えるのも目的どおりのため。失うのは、あとで休講日を削除したときの、個別の変更だけ（作り直される予定は、授業の今の値になる）。2026-10-19に決定。それまでの「未決定」）
- 送信中は、「追加する」ボタンを無効にして、「追加中…」と表示する。失敗したら、元に戻す（入力欄の値は、そのまま残す）

**削除**
- 各行の「削除」ボタンで削除する。確認のダイアログは出さない（休講日の日には、その学期の授業の自動生成の予定がないため、削除しても消える予定はない。削除で作られた予定は、もう一度追加すれば消え、削除の前の状態に戻る）
- 削除できたら、一覧に反映する
- 削除すると、その日の曜日の授業の予定（自動生成のもの）が作られる。その日に、同じ授業の単発の予定（補講など）を登録していた場合も作られ、両方が並ぶ（`architecture.md` の「同じ授業・同じ日付に単発の予定がある場合」）
- 削除中は、その行の「削除」ボタンを無効にして、「削除中…」と表示する。失敗したら、元に戻し、エラーメッセージを欄の上部に表示する（一覧は、取得し直さない）
- 日付・名前の変更の操作は用意しない（削除して、追加し直す）

**追加・削除の共通**
- 追加・削除を始めるときに、前の操作のエラーの表示を消す
- 追加・削除の途中で学期を切り替えた場合、その結果（成功・失敗）は、切り替えたあとの画面に出さない。追加・削除は、サーバーでは行われ、元の学期に戻ると、一覧に反映されている（`architecture.md` の「JavaScriptの構成」の、選択に依存する画面での登録・削除の規則）

**予定への反映の表示**
- 休講日の追加・削除で増減した予定の件数は、画面に出さない（予定は、カレンダーで確認する）

### 授業

**一覧**
- 選択中の学期の授業を、曜日→開始時刻の順に、表で表示する。列は、曜日（月〜日）・時間（「09:00 〜 10:00」）・科目名・教室・操作
- 操作の列（右寄せ）に、「編集」と「削除」のボタンを置く（「編集」「削除」を参照）。読み上げで、どの授業のボタンかを区別できるように、「「プログラミング基礎」（月 09:00 〜 10:00）を編集」「…を削除」の形の名前（`aria-label`）を付ける（同じ科目名の授業（週2回の授業など）を区別するため、曜日と時刻を含める）
- 詳細／メモは、科目名の下に小さく表示する（改行は、そのまま改行して表示する）。教室がないときは「—」を表示する
- 一覧の取得中は「読み込み中…」を表示する。取得に失敗したときは、エラーメッセージと「再読み込み」ボタンを表示する。授業が0件のときは、「この学期には、まだ授業が登録されていません」を表示する
- 「授業を追加」ボタンは、授業の見出しの右に置き、学期が選択されているとき（学期が1件以上あるとき）、常に表示する
- 過去の学期の授業データは削除・上書きせず、学期タブで見返せる。過去の学期にも、授業を追加できる（制限しない）

**登録フォーム（モーダル）**
- 「授業を追加」ボタンで開く。上部に、登録先の学期名を表示する（変更できない）
- 学期は授業ごとには聞かない。授業は、開いている学期タブの学期に所属する形で登録される（学期の登録は「学期（タブと登録）」を参照）
- 項目順：科目名（必須） → 教室（任意） → 曜日（月〜日。必須） → 開始時刻 → 終了時刻 → 詳細／メモ（任意、複数行）
  - 開始／終了時刻は、9〜19時の1時間刻みのプルダウン。開始時刻は9:00〜18:00、終了時刻は10:00〜19:00
  - 初期値は、月曜日、開始9:00、終了10:00
  - 開始時刻を変えて、終了時刻が開始時刻以下になったときは、終了時刻を、開始時刻の1時間後に、自動で合わせる
- ボタンは「閉じる」と「登録する」。空の項目（科目名）は、ブラウザ標準の入力チェックで止める。それ以外の入力チェックは、サーバー（API）が行い、結果を「入力エラーの表示」と同じように表示する（項目の下、または、フォームの上部）
- 送信中は、「登録する」ボタンを無効にして、「登録中…」と表示する。失敗したら、元に戻す

**連続登録**
- 登録に成功しても、モーダルは閉じない。入力欄をすべて初期値に戻し、科目名の欄にフォーカスを移し、登録済みのメッセージを表示する（次の登録の送信か、モーダルを閉じるまで）。一覧は、背後で更新される。1学期10科目前後を、続けて登録できる
- 登録済みのメッセージは、作成された予定（Event）の件数（APIの `generated_event_count`）によって、次のどちらかにする。「科目名」には、登録された科目名（前後の空白を取り除いたもの）が入る
  - 1件以上：「「科目名」を登録しました（予定N件を作成）」（Nは件数）
  - 0件：「「科目名」を登録しました（学期の期間内に、この曜日の授業日がないため、予定は作成されませんでした）」。「授業日」は、学期の期間内で、休講日を除いた日。期間内にその曜日の日がない場合と、その曜日の日がすべて休講日の場合の、どちらにも当てはまる
- モーダルを開くたびに、入力値・エラー表示・登録済みのメッセージを消して、初期値に戻す

**編集**（モーダル）
- 授業全体の編集は授業一覧から行い、今日以降（今日を含む）の、その授業の自動生成された予定が作り直される（作り直しの「今日」は、サーバーの日付。`architecture.md` の「授業全体の編集による作り直し」）。所属する学期は変えられない（誤った場合は、授業を削除して、正しい学期に登録し直す）。学期の休講日には、作り直しでも予定を作らない
- 一覧の行の「編集」ボタンで開く。登録とは別のモーダルにする（登録は、連続登録のため閉じない。編集は、保存したら閉じる。動きが違うため）
- 上部に、所属する学期名を表示し、その下に、「学期は変更できません。誤った場合は、授業を削除して、正しい学期に登録し直してください。」を小さく表示する
- 項目・並び・選択肢は、登録フォームと同じ（科目名・教室・曜日・開始時刻・終了時刻・詳細／メモ。時刻は、9〜19時の1時間刻みのプルダウン）
- 開くたびに、その授業の今の値（一覧に表示している値）を入力欄に入れ、エラー表示を消す。最初のフォーカスは、科目名の欄
- 今の開始時刻・終了時刻が、プルダウンの選択肢にない場合（APIで登録した授業など、9〜19時・1時間刻み以外の時刻）は、その時刻を、時刻の順の位置に選択肢として足して、選んだ状態で開く（足さないと、空欄になり、保存すると必須のエラーになるため）。足した選択肢は、次に開くときに取り除く
- 開始時刻を変えて、終了時刻が開始時刻以下になったときは、終了時刻を、開始時刻の1時間後に、自動で合わせる（登録と同じ）。1時間後の時刻が選択肢にないときは、変えない（APIの入力チェックで、誤りが表示される）
- 「保存する」ボタンの上に、次の注意書きを常に表示する。「保存すると、今日以降（今日を含む）のこの授業の予定が、新しい内容で作り直されます。カレンダーで個別に変更・削除した日も、元に戻ります。今日より前の予定と、カレンダーから追加した単発の授業（補講など）は、変わりません。」。要求定義の「保存前に確認メッセージ」は、この注意書きで満たす（保存のあとに、もう一度確認するダイアログは出さない。2026-10-14に決定）。「保存する」ボタンには、読み上げで、この注意書きが伝わるように、説明（`aria-describedby`）を付ける（2026-10-16に決定。015-L1）
- ボタンは「キャンセル」と「保存する」。空の項目（科目名）は、ブラウザ標準の入力チェックで止める。それ以外の入力チェックは、サーバー（API）が行い、結果を、登録フォームと同じように表示する（項目の下、または、フォームの上部）
- 保存では、すべての項目を送る（変えていない項目も、今の値のまま送る）。値が変わらなくても、今日以降の予定は作り直される（`architecture.md` の「授業全体の編集による作り直し」）
- 送信中は、「保存する」ボタンを無効にして、「保存中…」と表示する。失敗したら、元に戻す（モーダルは開いたまま）
- 保存できたら、モーダルを閉じ、一覧を取得し直す（メッセージは出さない。一覧の表示が変わるため）

**削除**（確認のモーダル）
- 授業全体の削除は授業一覧から行う。過去分を含む、その授業の予定（自動生成・単発とも）と課題がまとめて削除される
- 一覧の行の「削除」ボタンで、確認のモーダルを開く（ブラウザ標準の確認ダイアログ（`confirm`）は使わない。見た目をほかのモーダルとそろえ、エラーをモーダルの中に表示するため）
- モーダルには、上から、「「プログラミング基礎」（月 09:00 〜 10:00）を削除します。」、削除される予定と課題の件数「この授業の予定N件（今日より前の分を含む）と、課題M件も、まとめて削除されます。」（0件でも表示する）、「削除は取り消せません。」を表示する
- 件数は、モーダルを開くたびに、授業の1件取得のAPIの `event_count`・`task_count` で取得する（削除の直前の件数を出すため。`architecture.md` の「授業API」）。取得中は、件数の代わりに「予定と課題の件数を確認しています…」を表示し、「削除する」ボタンを押せない。取得に失敗したときは、エラーメッセージをモーダルの中に表示し、「削除する」ボタンは押せないまま（「キャンセル」で閉じて、開き直す）
- ボタンは「キャンセル」と「削除する」。最初のフォーカスは「キャンセル」（取り消せない操作のため）
- モーダルと「削除する」ボタンには、読み上げで、削除の対象・件数と「削除は取り消せません。」が伝わるように、説明（`aria-describedby`）を付ける（2026-10-16に決定。持ち越し015-L1）
- 削除中は、「削除する」ボタンを無効にして、「削除中…」と表示する。失敗したら、元に戻し、エラーメッセージをモーダルの中に表示する（モーダルは開いたまま）
- 削除できたら、モーダルを閉じ、一覧を取得し直す（メッセージは出さない。一覧から行が消えるため）

**編集・削除の共通**
- モーダルを閉じて、開き直したあとに、前に開いたときの操作の結果（成功・失敗、件数）が届いても、開き直したモーダルの表示は変えず、閉じない。一覧は取得し直す（`architecture.md` の「JavaScriptの構成」の、モーダルの中で始める要求の規則）

## 課題・タスクモード
課題と、その他（締切のみ）の、一覧・追加（課題だけ）・完了の切り替え・編集・削除（2026-10-16に決定）。カレンダーへの締切の表示（週表示の「締切」の行、月表示の印、「直近の締切」欄、締切の詳細パネル）は、「カレンダーモード」に書く。

### 一覧
- 「未完了」と「完了」の2つの表を、上下に並べる（見出しは「未完了」「完了」）。「課題を追加」ボタンは、「未完了」の見出しの右に置く
- データは、課題・タスクのAPIの一覧（`GET /api/tasks`）を1回取得し、画面で、未完了と完了に分ける
- 並びは、未完了が、締切日時の早い順（期限切れが上に来る）。完了が、締切日時の新しい順（APIの並び（締切日時・idの昇順）の逆）
- 列は、完了（チェックボックス）・締切・課題名・対象授業・操作の5つ。2つの表で、列の幅をそろえる
  - 締切：「2026年10月20日（火） 23:59」の形（曜日つき。日付の表示は、休講日と共通。`architecture.md` の「JavaScriptの構成」の `dates.js`）
  - 課題名：タイトルの前に、カテゴリのアイコン（課題＝✅、その他＝⭐）を付ける。アイコンは読み上げず、代わりに、カテゴリの表示名（「課題：」「その他：」）を、見えない文字で添える。詳細／メモは、タイトルの下に小さく表示する（改行は、そのまま改行して表示する）
  - 対象授業：授業の科目名（APIの `subject_name`）。その他（締切のみ）は「—」
  - 課題名（詳細／メモを含む）と対象授業のセルは、区切れる場所のない長い文字列（空白のない長いURLなど）も、折り返して表示する（右の列にはみ出さないため。2026-10-18に決定）
  - 操作（右寄せ）：「編集」と「削除」のボタン
- チェックボックスと「編集」「削除」のボタンには、読み上げで、どの課題・タスクのものかを区別できるように、「「レポート第1回」（締切 2026年10月20日（火） 23:59）の完了」「…を編集」「…を削除」の形の名前（`aria-label`）を付ける（同じタイトルの課題・タスクを、締切で区別するため）
- 期限切れ：未完了で、締切日時が、今（ブラウザの日付・時刻。分まで）より前のものは、締切の横に、赤い「期限切れ」の印を付ける。締切日時と同じ分は、まだ期限切れではない。完了の表には付けない。判定は、一覧を表示するときに行う（表示したまま時間が過ぎても、表示し直すまで変わらない）
- 0件のときは、表の代わりに、「未完了の課題・タスクはありません」「完了した課題・タスクはありません」を表示する
- 課題・タスクのモードを開くたびに、一覧を取得し直す（授業モードでの授業の削除（その授業の課題も削除される）を反映し、期限切れを、開いたときの日時で判定するため）
- 取得中は「読み込み中…」を表示する。取得に失敗したときは、エラーメッセージと「再読み込み」ボタンを表示する（授業の一覧と同じ）
- 期限型のその他（締切のみ）も、同じ一覧に載せる。その他の追加の入口は、カレンダーの追加フォーム（「その他」の「締切のみ」。「カレンダーモード」の「予定の追加」）だけで、このモードの「課題を追加」は、課題専用（2026-10-18・2026-10-19に決定）

### 完了の切り替え
- 行のチェックボックスを押すと、すぐに保存する（`PATCH` で `is_completed`）。確認のダイアログは出さない。完了の取り消しは、完了の表のチェックを外して行う
- 保存中は、そのチェックボックスを押せなくする。保存できたら、一覧を取得し直す（行が、もう一方の表へ移る）
- 失敗したら、チェックを元に戻し、エラーメッセージを、一覧の上部に表示する。次の切り替えを始めるときと、モードを開き直したときに消す

### 追加（モーダル）
- 「課題を追加」ボタンで開く。見出しは「課題を追加」
- 項目順：課題名（必須） → 対象授業（必須） → 締切日・締切時刻（必須） → 詳細／メモ（任意、複数行）
  - 対象授業：プルダウン。選択肢は、今の学期の授業だけ（科目名。並びは、授業の一覧と同じ、曜日・開始時刻の順）。先頭は「選択してください」（値は空。必須のため、選ばないと、ブラウザ標準の入力チェックで止まる）
    - 今の学期は、授業モードで最初に選ばれる学期と同じ規則で決める（「授業モード」の「学期（タブと登録）」の「初期選択」の1〜3。「今日」は、ブラウザの日付）。前期・後期で、授業の課題は分かれ、学期が変わると、前の学期の課題は追加しないため（2026-10-16に決定）
    - 同じ学期に、同じ科目名の授業が2つある場合（週2回の授業など）は、同じ名前の選択肢が2つ並ぶ（千葉工業大学では、同じ科目名の授業が週2回あることは、ほとんどないため、区別の表示はしない）
    - 授業の一覧は、モーダルを開くたびに取得する（授業モードで登録した授業を反映するため）。取得中は、欄の下に「授業を読み込み中…」を表示する
    - 欄の下に、どの学期の授業かを表示する（「2026年度 後期の授業から選びます」）。学期が1件もないときは「学期が登録されていません。授業モードで、学期と授業を登録してください」、今の学期に授業がないときは「2026年度 後期には、授業が登録されていません。授業モードで、授業を登録してください」（選択肢は「選択してください」だけになり、登録できない）
    - 取得に失敗したときは、エラーメッセージを、フォームの上部に表示する（選択肢は「選択してください」だけ。モーダルを閉じて、開き直す）
  - 締切日・締切時刻：日付と時刻の2つの入力欄。締切時刻の初期値は「23:59」（課題は、23:59の締切が多いため）。締切日の初期値は、空欄。APIには、2つをつないだ日時（`YYYY-MM-DDTHH:MM`）を送る
- ボタンは「キャンセル」と「登録する」。空の項目は、ブラウザ標準の入力チェックで止める。それ以外の入力チェックは、サーバー（API）が行い、結果を、該当する入力欄の下に表示する（締切日時のエラーは、締切日・締切時刻の下に、まとめて表示する）。項目に結びつかないエラーは、フォームの上部に表示する
- 課題名の欄の名前は「課題名」だが、APIのエラーメッセージは「タイトル」（例：「タイトルは必須です」）のまま表示する（エラーは、課題名の欄の下に出るため、どの欄の誤りかは分かる。2026-10-16に決定）
- 送信中は、「登録する」ボタンを無効にして、「登録中…」と表示する。失敗したら、元に戻す（モーダルは開いたまま）
- 登録できたら、モーダルを閉じ、一覧を取得し直す（メッセージは出さない。連続登録はしない）
- 開くたびに、入力値・エラー表示を消して、初期値に戻す。最初のフォーカスは、課題名の欄

### 編集（モーダル）
- 一覧の行の「編集」ボタンで開く。カレンダーの締切の詳細パネルの「編集」からも、同じモーダルを開く（2026-10-19）。追加とは別のモーダル。見出しは、課題は「課題を編集」、その他（締切のみ）は「その他（締切のみ）を編集」
- 項目は、課題が、課題名・対象授業・締切日・締切時刻・詳細／メモ。その他（締切のみ）は、タイトル・締切日・締切時刻・詳細／メモ（対象授業の欄を出さない。その他は、授業を指定できないため）。カテゴリと、完了の状態は、編集のモーダルでは変えない（カテゴリは変えられない。完了は、一覧のチェックボックスで切り替える）
- 開くたびに、その課題・タスクの今の値（一覧に表示している値）を入力欄に入れ、エラー表示を消す。最初のフォーカスは、課題名（タイトル）の欄
- 対象授業（課題だけ）：選択肢は、追加と同じく、今の学期の授業（モーダルを開くたびに取得する。欄の下の表示も、追加と同じ）。今の対象授業が、今の学期の授業にない場合（前の学期の授業の課題）は、その授業を、選択肢に足して、選んだ状態で開く（足さないと、空欄になり、保存すると必須のエラーになるため）。授業の一覧の取得中と、取得に失敗したときは、今の対象授業だけを選んだ状態にする（ほかの項目は、保存できる）
- 保存では、すべての項目を送る（変えていない項目も、今の値のまま送る。対象授業は、課題だけ）
- ボタンは「キャンセル」と「保存する」。入力チェックとエラーの表示は、追加と同じ
- 送信中は、「保存する」ボタンを無効にして、「保存中…」と表示する。失敗したら、元に戻す（モーダルは開いたまま）
- 保存できたら、モーダルを閉じ、一覧を取得し直す（メッセージは出さない）

### 削除（確認のモーダル）
- 一覧の行の「削除」ボタンで、確認のモーダルを開く（ブラウザ標準の確認ダイアログ（`confirm`）は使わない。授業の削除と同じ）。カレンダーの締切の詳細パネルの「削除」からも、同じモーダルを開く（2026-10-19）。見出しは「課題・タスクを削除」
- モーダルには、上から、「「レポート第1回」（締切 2026年10月20日（火） 23:59）を削除します。」と、「削除は取り消せません。」を表示する（課題・タスクは、一緒に削除されるデータを持たないため、件数は出さない）
- モーダルと「削除する」ボタンには、読み上げで、削除の対象と「削除は取り消せません。」が伝わるように、説明（`aria-describedby`）を付ける
- ボタンは「キャンセル」と「削除する」。最初のフォーカスは「キャンセル」（取り消せない操作のため）
- 削除中は、「削除する」ボタンを無効にして、「削除中…」と表示する。失敗したら、元に戻し、エラーメッセージをモーダルの中に表示する（モーダルは開いたまま）
- 削除できたら、モーダルを閉じ、一覧を取得し直す（メッセージは出さない）

### 追加・編集・削除の共通
- モーダルを閉じて、開き直したあとに、前に開いたときの操作の結果（成功・失敗、授業の一覧）が届いても、開き直したモーダルの表示は変えず、閉じない。一覧は取得し直す（`architecture.md` の「JavaScriptの構成」の、モーダルの中で始める要求の規則。授業の編集・削除と同じ）
- 編集・削除できたら、カレンダーの締切と「直近の締切」欄にも反映する（カレンダーの締切の詳細パネルから開いた場合も、一覧から開いた場合も。`architecture.md` の「モード間の連携」の `task-changed`）

### カレンダーとの関係
- 完了／未完了の切り替えは、一覧・「直近の締切」欄・締切の詳細パネルのどこからでも1クリックで行う。確認ダイアログは出さない。完了の取り消しは完了一覧から行える（締切の詳細パネルでは、開いている間なら、チェックを外して戻せる）
- 完了にしたものは、カレンダー上（週・月表示）の締切表示と「直近の締切」欄から消え、完了一覧でのみ確認できる

## 色・アイコン
- カテゴリごとに色分けする。赤と緑のような区別しづらい組み合わせは避け、青系・オレンジ系・緑系・グレー系のように離れた色を割り当てる
- 色だけに頼らず、カテゴリごとに小さなアイコンも添える（授業＝本、課題＝チェックの印、アルバイト＝カバン、その他＝星）。詳細パネルや一覧に使う
- 時間型は色のブロック、期限型は●の印（カテゴリの色）とタイトル、という形の違いでも見分けられるようにする（2026-10-18に、ピルから●の印に変えた。月表示で、時間型のブロックと形で見分けるため）
- 色とアイコンの値（2026-10-13に決定）

  | カテゴリ | 色（背景） | 文字の色 | アイコン |
  |---|---|---|---|
  | 授業 | 青 `#0a58ca` | 白 `#ffffff` | 📖 |
  | 課題 | オレンジ `#fd7e14` | 黒 `#000000` | ✅ |
  | アルバイト | 緑 `#146c43` | 白 `#ffffff` | 💼 |
  | その他 | グレー `#6c757d` | 白 `#ffffff` | ⭐ |

  - 背景と文字の色の組み合わせは、どれもコントラスト比4.5以上（文字が読みやすい基準）
  - アイコンは、絵文字の文字で表す（アイコンのライブラリを使わない）。読み上げでは読ませない（絵文字の名前が読まれて、かえって分かりにくくなるため。詳細パネルでは、表示名をアイコンの横に表示する）
  - カレンダーでは、予定のブロック（週・月）と、一覧表示の行の印（●）、締切の●の印（週・月）に、カテゴリの色を使う。絞り込みのチェックボックスに、色の見本を添える。アイコンは、一覧表示の行、詳細パネル（予定・締切）、「直近の締切」欄に付ける（週・月の表示の予定・締切には付けない）
  - その他は、予定（時間指定あり）と課題・タスク（締切のみ）で、同じ色・アイコンを使う
- DBに保存するカテゴリの値（予定（Event）：授業＝`class`、アルバイト＝`part_time`、その他（時間指定あり）＝`other`。課題・タスク（Task）：課題＝`assignment`、その他（締切のみ）＝`other`）と、画面に出す表示名・色・アイコンの対応は、画面側の対応表で持つ（`architecture.md` の「データ設計」。対応表は `app/static/js/categories.js`、色の値は `app/static/css/style.css`）
