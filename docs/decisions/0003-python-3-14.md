# 0003 開発の環境とCIのPythonを、3.11から3.14へ移す

- 状態：採用
- 日付：2026-10-27
- 決定：Koma（Task 024の設計で、案A を承認）。案：Claude

## 背景
- このアプリは、Python 3.11 で作ってきた（KomaのMacは 3.11.5。pyenv で入れたもの。CIは 3.11 の最新の修正版）
- 3.11 は、修正がセキュリティだけの時期で、2027-10 に終わる。python.org の配布物（組み立て済みのもの）は 3.11.9 が最後で、それより新しい修正（2026-10-25 の 3.11.18 など）は、ソースだけで出る
- KomaのMacの 3.11.5（2023-08）には、その後のセキュリティの修正が入っていない
- 2026-10-25 に、3.14.10 が、急ぎのセキュリティの修正版として出た。eMudhra の中間CAの鍵の侵害（ADR 0002）への対応（`ssl` が、侵害された鍵を拒む）や、`tarfile` の修正を含む
- Pythonの版の状態（2026-10-27。python.org の「Active Python releases」）

| 版 | 状態 | 終わり |
|---|---|---|
| 3.15 | 修正が続く（2026-10-09 に公開） | 2031-10 |
| 3.14 | 修正が続く（2025-10-07 に公開） | 2030-10 |
| 3.13 | セキュリティの修正だけ | 2029-10 |
| 3.11 | セキュリティの修正だけ | 2027-10 |

- Task 024の設計で、作業環境の 3.14 で試した：すべての依存に、Mac用の組み立て済みのファイル（wheel）がある。E2Eは合格。pytestは2件失敗した（下の「影響」の `24:00`）

## 決定
1. 開発の環境（KomaのMac）とCIの Python を、3.14 にする
2. KomaのMacは、pyenv で 3.14.10 を入れ、`.venv` を作り直す。3.14.10 は、公開から2週間たっていないが、急ぎのセキュリティの修正版のため、版の規則の例外とする（Komaの承認、2026-10-27）
3. CIは、3.14 の最新の修正版を使う（`check-latest`。CIの Python の修正版は、版の規則の対象外）
4. 3.14 の修正版（3.14.x）は、セキュリティの修正が出たら、Macでも上げる（pyenv で入れ、`.venv` を作り直す）。手順と方針は `architecture/security.md` の「開発の環境」

## 理由
- 3.14 は、修正が続く時期で、2030-10 まで使える。Task 026（クラウドへの公開）のころに、版を移す作業が重ならない
- 今のコードと依存は、ほぼそのまま動く（直すのは1か所）
- 3.14 の修正版には、Mac用の配布物もある（pyenv でも、ソースから入れられる）

## 代替案
| 案 | 採らなかった理由 |
|---|---|
| 3.11 のまま、最新の 3.11.18 にする（pyenv でソースから入れる） | コードは変わらないが、3.11 は1年で終わり、公開のころに結局移ることになる |
| 3.15 にする | サポートは最も長いが、出てから3週間。`MarkupSafe 3.0.3` などに3.15用のファイルがなく、依存の更新が増える（版の規則にも当たりやすい） |
| 3.13 にする | すでにセキュリティの修正だけの時期で、3.11 と同じ問題が、少し遅れて起きる |
| 別のタスクに分ける | PRは小さくなるが、Macでの確認が2回になる（Task 024のヘッダーの確認と、1回で済ませる） |

## 影響
- 3.14 の `datetime.fromisoformat` は、`24:00` を翌日の0時として受け付ける。日時（`YYYY-MM-DDTHH:MM`）の変換を、日付と時刻の厳密な変換の組み合わせに変え、仕様（時刻は `00:00`〜`23:59`）どおりに断る（`app/api_helpers.py` の `parse_datetime`。既存のテストが、3.14で確かめる）
- 3.14 の `json` は、入れ子が1万段のJSONも読める（3.11 は約1000段で `RecursionError`）。入れ子が深すぎるJSONのテストは、版によらず `RecursionError` になる深さで行う（Task 024）
- `CLAUDE.md`・`README.md`・`architecture/overview.md`・`development/testing.md`・CIの版の記載を、3.14 にする
- KomaのMacで、pyenv で 3.14.10 を入れ、`.venv` を作り直し、Playwright のブラウザを入れ直す（Task 024のPRの説明に手順）
- Task 026（クラウドへの公開）のホストは、Python 3.14 を使えるものを選ぶ
- 3.14 の修正が続く時期（2027-10ごろまで）が終わり、セキュリティの修正だけになったら、新しい版へ移るかを、改めて決める
