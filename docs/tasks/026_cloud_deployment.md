## 目的
Macを開かなくても、スマホから使えるようにする。インターネットのだれからでも届くことを前提に、Task 025 までの守りを、公開の形（HTTPS・プロキシの後ろ・共有ホスティング）に合わせて固める。実データを、漏らさず・失わずに、クラウドへ移す。

## 範囲
1. 本番の設定：明示の設定で「公開」を決め、Host・Origin・Cookie・HSTS・秘密の鍵・DBの場所を、そこから決める。設定がおかしければ起動しない。Web とコマンドで同じ設定を使う
2. 接続元：プロキシが付けるヘッダーのうち、上書きされると確かめた1つだけを読む
3. 日本時間の「今日」
4. ログインの守り：端末の印（025-D1）、失敗の行の全体の上限、パスワードの確かめの枠、ワーカーの数の確かめ
5. データ：本番のDB、本番で壊す操作を断る、整理つきの毎日のバックアップ、移行の写し
6. 仕様の変更：メモ2,000字、学期の期間366日以内、本番にデモの利用者を置かない、本文の上限
7. スマホでの最低限の表示（崩れを直す。見た目の作り込みは段階3）
8. 本番の点検のスクリプト（Macから動かす）と、手順書（下見・デプロイ・移行・バックアップ）
9. 資料・ADR 0005・roadmap（Task 025 の完了、D-48）・`database.md` の手順の順番（`rename-user` を先に）・`dependabot.yml`（pyee 15以上を除外）

## 非対象
- Postgres などへのDBの変更（SQLite のまま）。`postgres://` の形のURL、pepper（DBとアプリが同じ場所のため。ADR 0005）
- 独自のドメイン（費用がかかる）。新規登録・パスワードの再設定などの段階4の機能
- 見た目の作り直し（段階3）。失敗が多いことを知らせる仕組み（任意とした）
- Claude が本番に触れること（本番の認証の情報も、本番への通信も持たない。本番の作業は Koma）

| 印のある道 | 印が有効で、その持ち主のログインIDが、打ち込まれたIDと完全に一致するときは、IDごと・接続元ごとの制限と全体の上限を当てない。代わりに、パスワードを確かめる前に、印の失敗の数を増やす（5回未満のときだけ。1つずつの処理の中）。5回で印を無効にする（ログに残す）。成功したら、印を作り替え、数を戻す。【レビューで足した】有効な印が、持ち主と違うIDと一緒に届いたら、印のない道で扱い、印の失敗にも数える（盗まれた印で、持ち主のIDを探らせない。試せる候補は5回まで） | `architecture/security.md` の「ログインの試行の制限」 |

## 受け入れ条件
- 本番の設定が足りない・形が違う（`APP_ENV` の書き間違い、`http://` の `PUBLIC_ORIGIN`、`SECRET_KEY` がない・短い、相対パス・リポジトリの中のDB、`CLIENT_ADDRESS_HEADER` がない）とき、Web もコマンドも起動しない
- 本番の設定では、Cookie が `__Host-` の名前で `Secure`、HSTS が付く。`PUBLIC_ORIGIN` と違う Host は400、違う `Origin` の書き込みは403、`X-Forwarded-Proto` が `https` でない要求は400
- 接続元は、決めたヘッダーだけから決まる。`X-Forwarded-For` などを偽っても変わらない。ヘッダーがない要求は400
- 印のある端末は、IDごと・接続元ごとの制限と全体の上限の間も、ログインできる（今の xfail のテストを、印のある端末で通るように直す）。印のない新しい端末は、今までどおり制限される（受け入れた弱さとして残す）。印で5回失敗すると、印が使えなくなる。同時の要求で、5回を超えて試せない
- 直近1時間の失敗が300以上で、印のない道は、記録も計算もせずに503
- 「今日」が日本時間になる（日本の0時〜9時（UTC の15時〜24時）でも、日本の日付）
- 本番で、壊す操作のコマンドが断られる。`daily-backup` が30個を残す。`make-transfer-copy` の写しが、上の確かめを満たし、元のDBが変わらない
- メモ・学期の期間・本文の上限が、決めたとおりに断る
- iPhone の幅（390px）で、主な画面が横にはみ出さず、カレンダーが「一覧」で始まる
- `python -m pytest`、`python -m pytest -m e2e`、`ruff check .`、`npm run lint` が通り、CIの3つのジョブが合格する
- 実データのDBに触れない（`tests/conftest.py` の守りは、そのまま）
- 本番の確認（Koma。手順書）：下見で、点検のスクリプトがすべて合格し、iPhone の Safari（HTTPS）で、ほかのサイトのリンクから開いたときの開き直し、ログアウトの後の「戻る」（ボタンとスワイプの画面の写し）、端末の印を確かめる

## テストの観点
- 設定：本番の必須の項目ごとの欠け・形の誤り、ローカルで `PUBLIC_ORIGIN` を付けたとき、本番から決まる値、コマンドの表示、`run.py` の拒否、ワーカーの数（`uwsgi` を差し替える）
- 接続元の層：ヘッダーの有無・アドレスでない値・複数の値、`X-Forwarded-For` の偽装、`X-Forwarded-Proto`、HSTS、Cookie の名前と属性
- 日本時間：UTC の 14時59分・15時（日本の日付が変わる境目）の前後で、授業の編集の基準・バックアップの名前が日本の日付。`date.today()`・`datetime.now()` の使用がないこと
- 端末の印：作る・作り替える・10個まで・期限・別の利用者の印・IDの大文字や空白の違い・パスワードのない利用者・5回で無効・同時の要求・`set-password` と「すべての端末から」で消える・ふつうのログアウトで残る・制限の間のログイン
- 全体の上限：しきい値の前後、印のある道は通る、記録しない
- データ：本番の実データのDBの判定、壊す操作の拒否（`downgrade`・`stamp` を含む）、`daily-backup` の作成・整理・失敗、`make-transfer-copy` の消す表・空き領域・件数・元のDBが変わらない・出力先の検査
- 仕様：メモ 2,000字・2,001字（前後の空白を除いて）、学期 366日・367日（`POST`・`PATCH`）、64KiB を超える本文（API の JSON）
- E2E：iPhone の幅での主な画面（はみ出し・カレンダーの最初の表示・課題の表）。ブラウザの時間帯を日本にする
- 点検のスクリプト：判定の関数（ヘッダー・Cookie の属性）を、作った応答で確かめる

## 確認の方法
- Claude：上のコマンドを、作業環境の Python 3.14 で実行する（E2Eは `E2E_CDN_FROM_NPM=1`）。本番の設定で一時的なDBのアプリを作り、ヘッダー・Cookie・接続元を確かめる
- 役割を分けたAIエージェント（Claudeが起動し、結果を確かめて取り込む。取り込まなかったものは理由をPRに残す）
